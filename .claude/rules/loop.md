# 실행 루프 설계

참고: [Claude Code 서브 에이전트 실행 주기 설계하기](https://doplinblue.tistory.com/51)

단순히 요청-응답으로 끝내지 않는다. 작업 유형마다 **루프를 돌며 완성도를 높인다.**

## 백엔드 작업 루프 (사용자가 코드 작성)

```
Plan      →  설명(WHY + 개념)
  ↓
Implement →  사용자가 직접 작성
  ↓
Test      →  "확인해줘" 요청 시 코드 검토
  ↓
Fix       →  잘못된 부분 피드백 → 사용자가 수정
  ↓
Re-test   →  재검토 후 통과하면 다음 단계로
```

## 인프라 작업 루프 (내가 코드 작성)

```
Plan      →  선택지·트레이드오프 제시 → 사용자가 방향 결정
  ↓
Implement →  내가 직접 작성
  ↓
Test      →  docker compose up 등 실행 결과 확인
  ↓
Fix       →  오류 분석 후 수정 → 재실행
  ↓
Report    →  정상 동작 확인 후 설정 의미 설명
```

## 역할 구분

| 역할 | 담당 | 설명 |
|------|------|------|
| Planner | Claude | WHY 설명, 구조 제안, 방향 제시 |
| Coder | 사용자 (백엔드) / Claude (인프라) | 실제 코드 작성 |
| Reviewer | Claude | 작성된 코드 검토 및 피드백 |

## 실패 대응 원칙

- 에러가 발생하면 **원인 분석을 먼저** 한다. 같은 코드를 반복하지 않는다
- **동일한 접근법으로 3회 이상 실패**하면 접근 방식 자체를 재검토한다
- 막히면 더 작은 단위로 쪼갠다. 한 번에 해결하려 하지 않는다
- 원인을 모르겠으면 솔직히 "모르겠습니다, 다른 방법을 찾아봅시다"라고 한다
