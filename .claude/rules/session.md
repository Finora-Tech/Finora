# 세션 루틴 규칙

## 세션 시작

### 1. 날짜 확인 및 일정 파일 체크

1. **오늘 날짜 확인** (형식: YYMMDD, 예: 260223)
2. **주간 계획 파일 확인**: `todo/YYMMDD(월)ToYYMMDD(일).md`
3. **오늘 할 일 파일 확인**: `todo/YYMMDD.md`

### 2. 월요일이면 — 주간 계획 파일 생성

파일이 없으면 **자동으로 생성**한다.

- 파일명: `todo/YYMMDD(월)ToYYMMDD(일).md` (예: `todo/260302To260308.md`)
- 직전 주 완료 내역을 참고해 이번 주 목표를 제안한다
- README.md의 Roadmap 현재 주차를 기준으로 스프린트 목표를 설정한다
- 세션 계획은 **최소 3회** (예: 월/수/금 또는 월/수/토)

### 3. 매 세션마다 — 오늘 할 일 파일 생성/확인

- `todo/YYMMDD.md` 파일이 없으면 **자동으로 생성**한다
- 주간 계획의 해당 회차 목표를 기반으로 오늘 할 일 목록을 작성한다
- **scope out 섹션 필수**: 오늘 하지 않을 것을 명시해 범위를 제한한다

## 세션 종료

### ① 할 일 파일 업데이트

- 오늘 완료된 항목에 체크 표시
- 주간 계획의 해당 회차 완료 체크
- 다음 회차에 이월할 내용 메모

### ② 커밋 메시지 제안

세션에서 변경된 파일을 확인하고 커밋 메시지를 채팅으로 제안한다.
제목 + 세부 내용(변경 파일별 요약) 형식으로 작성한다.
(실제 커밋은 사용자가 직접 수행)

### ③ 블로그 초안 작성

| 상황 | 글 유형 | 템플릿 |
|------|---------|--------|
| 에러/버그를 해결했거나 예상치 못한 문제를 마주쳤을 때 | 트러블슈팅 | `docs/blog-template-troubleshooting.md` |
| 설계 결정, 기능 구현, 또는 세션 전반을 돌아볼 때 | 회고 | `docs/blog-template-retrospective.md` |

- 두 상황이 모두 해당하면 트러블슈팅 우선
- 블로그 초안은 `docs/blog/YYMMDD-{slug}.md`로 저장한다
- 백엔드 구현 코드 스니펫은 포함하지 않는다. 결정의 이유와 트레이드오프에 집중한다
- 마지막에 "오늘의 한 줄" 인용구 포함
- 초안 생성 후 "블로그 초안을 작성했습니다. 확인 후 티스토리에 올려보세요." 안내
